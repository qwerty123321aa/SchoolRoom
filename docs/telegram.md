# Подключение Telegram к SchoolRoom

## Что уже было и что добавлено

API уже проверял `Telegram.WebApp.initData`: HMAC-SHA-256 с токеном бота, сравнение
подписи через `timingSafeEqual`, срок действия `auth_date`, допуск времени в будущем
30 секунд, ограничение размера 16 КБ, запрет повторяющихся параметров. Проверка
сохранена. Поле `signature`, когда оно присутствует, участвует в HMAC вместе с
остальными полями, кроме `hash` (это отличается от сторонней Ed25519-проверки).
Telegram ID сохраняется в существующей таблице users через существующий repository.

Добавлено:

- Отдельное приложение `apps/bot`: `/start` с кнопкой Mini App, `/id` и `/help` в личном чате.
- `/start` передаёт Telegram ID и профиль во внутренний API с HMAC-подписью, после чего API
  сохраняет пользователя через существующий repository. Токен бота в запрос не передаётся.
- Взаимоисключающие режимы polling/webhook. Бот не меняет проекты и не обращается к БД напрямую.
- Защищённый `GET /api/v1/me` с существующей авторизацией. ID в JSON передаётся строкой.
- Отдельные команды настройки меню и webhook. Обычный запуск бота ничего не регистрирует
  и не удаляет в настройках Telegram.
- Тесты транспорта, повторной доставки, ошибок, конфигурации и реальной HMAC-цепочки API.

Фронтенды уже подключают Telegram JS SDK и передают сырые `initData` в заголовке
`Authorization: tma <initData>`. UI и бизнес-логика каталога не изменены.
Новых миграций для этого этапа нет.

## Значения, которые нужно добавить вручную

Храните секреты в корневом `.env` (он исключён из Git) или секретах окружения хостинга.
Не вставляйте токен в исходники, URL приложения, браузерную консоль, чат или команды shell.
Переменные среды процесса имеют приоритет над `.env`.

| Переменная | Что указать |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен вашего бота от @BotFather. Один и тот же токен для API и Bot. Никогда не добавлять префикс `VITE_`. |
| `TELEGRAM_BOT_MODE` | `polling` для разработки, `webhook` для размещённого сервиса, `disabled` для отключения. |
| `TELEGRAM_MINI_APP_URL` | Полный HTTPS-адрес существующего Mini App, доступный пользователю в Telegram. |
| `SCHOOLROOM_API_URL` | Внутренний origin API для процесса бота; по умолчанию `http://127.0.0.1:4100`. Разрешён HTTPS или loopback HTTP. |
| `TELEGRAM_AUTH_MAX_AGE_SECONDS` | Срок действия initData; по умолчанию 3600 секунд. После истечения приложение нужно открыть заново из Telegram. |
| `ADMIN_TELEGRAM_IDS` | Реальные ID администраторов через запятую; узнать собственный ID можно через `/id`. |
| `DEV_AUTH_ENABLED` | `false` для реальной Telegram-проверки и production. |
| `VITE_DEV_TELEGRAM_USER_ID` | Пустое значение для реального Telegram-запуска. |
| `VITE_DEV_ADMIN_TELEGRAM_USER_ID` | Пустое значение для реального Telegram-запуска. |
| `CORS_ORIGINS` | Точные разрешённые адреса Mini App и Admin, если они обращаются к API на другом origin. |
| `VITE_API_URL` | `/api/v1` при едином origin и reverse proxy либо публичный HTTPS-адрес API с `/api/v1`. |

Только для webhook:

| Переменная | Что указать |
| --- | --- |
| `TELEGRAM_WEBHOOK_URL` | Публичный HTTPS-адрес, заканчивающийся `/telegram/webhook`; без токена, query-параметров и fragment. |
| `TELEGRAM_WEBHOOK_SECRET` | Независимый случайный секрет: 32–256 символов `A-Z a-z 0-9 _ -`. Можно сгенерировать локально `openssl rand -hex 32`. |
| `BOT_HOST` | По умолчанию `127.0.0.1`; `0.0.0.0` для контейнера, когда доступ ограничен reverse proxy. |
| `BOT_PORT` | Внутренний порт процесса бота, по умолчанию `4200`. |

Пример `.env.example` содержит пустые значения для секретов.
Не заменяйте существующий `.env` целиком: добавьте новые поля и сохраните настройки БД.
Изменения `VITE_*` требуют перезапуска Vite, а при production — новой сборки фронтендов.

## Первый запуск: long polling

1. Создайте бота в @BotFather и вручную добавьте токен в окружение API и Bot.
2. Настройте HTTPS-адрес Mini App и `TELEGRAM_BOT_MODE=polling`.
3. Установите зависимости `pnpm install --frozen-lockfile`.
4. Выполните `pnpm bot:configure status` для проверки токена и наличия webhook.
5. Если webhook уже настроен и вы намеренно переходите на polling: сначала остановите
   webhook-процесс, затем выполните `pnpm bot:configure webhook:delete`.
   Очередь ожидающих обновлений при этом сохраняется.
6. Выполните `pnpm bot:configure menu`: зарегистрирует `/start`, `/id`, `/help` и кнопку меню Mini App.
7. Запустите API и фронтенды через `pnpm dev`, бот — в отдельном терминале `pnpm dev:bot`.
8. Откройте личный чат с ботом, отправьте `/start`, нажмите «Открыть SchoolRoom».

Polling не требует публичного входящего порта бота. Однако Mini App всё равно нужен
доступный из Telegram HTTPS-адрес. Приватная ссылка Codespace с GitHub sign-in не является
готовым адресом для пользователей Telegram. Публичность портов эта реализация не меняет.
Admin и PostgreSQL не следует публиковать ради запуска Mini App.

## Webhook для размещённого сервиса

1. Остановите polling-процесс. Выберите `TELEGRAM_BOT_MODE=webhook`, заполните URL и секрет.
2. Выполните `pnpm build`, затем `pnpm start:bot` под менеджером процессов.
3. Настройте TLS reverse proxy: внешний `POST /telegram/webhook` направляется на
   `http://127.0.0.1:4200/telegram/webhook` (либо адрес контейнера). Заголовок
   `X-Telegram-Bot-Api-Secret-Token` должен передаваться без изменений. Ограничьте
   размер тела до 64 КБ и не записывайте тела/секретные заголовки в access logs.
4. Проверьте локальный `http://127.0.0.1:4200/health` — он показывает только состояние
   listener, а не факт настройки webhook в Telegram.
5. Зарегистрируйте доставку: `pnpm bot:configure webhook:set`, затем `pnpm bot:configure status`.
6. Проверьте `/start`, `/id`, `/help` и открытие Mini App в Telegram.

Webhook регистрируется с `allowed_updates=[message]`, `max_connections=1`,
`drop_pending_updates=false`. Для публичного адреса используется поддерживаемый Telegram
HTTPS-порт (обычно 443); внутренний 4200 не указывается в публичном URL.
При остановке процесса webhook остаётся зарегистрированным: Telegram сможет повторить
доставку. Для перехода обратно на polling удалите webhook отдельной командой.

## Проверка пользователя

`GET /api/v1/me` принимает `Authorization: tma <сырое Telegram.WebApp.initData>`:

```json
{
  "user": {
    "id": "22222222-2222-4222-8222-222222222222",
    "telegramId": "100000001",
    "name": "Example user",
    "username": null
  }
}
```

Значения в примере вымышленные. Ответ `private, no-store`. Поддельные, просроченные,
подписанные другим ботом данные дают 401 до записи пользователя в БД. Параметр
`telegramId` в URL и `initDataUnsafe.user` не подтверждают личность. При неверном
`Authorization` сервер не переходит на development-заголовок.
Существующий dev-режим оставлен только для локальной разработки, production запрещает его.

`/start` использует `message.from.id` из обновления Telegram и отправляет профиль только на
настроенный SchoolRoom API. Запрос подписывается ключом, производным от токена бота, с временной
меткой и принимается API в течение 30 секунд. `/id` только показывает `message.from.id` самому
пользователю. Запрос Mini App проверяется отдельно через initData; webhook-секрет не заменяет
пользовательскую авторизацию. Ни ID из команды, ни переданный клиентом ID не дают
административных прав автоматически.

## Проверки и эксплуатационные границы

Автоматические проверки: `pnpm typecheck`, `pnpm test`, `pnpm build`.
Они не обращаются к реальному Telegram: используются искусственные подписи и подменённый
HTTP transport. `pnpm start:bot` без настройки режима выводит `disabled` и не выходит в сеть.

- Неправильный webhook-секрет — 401; неправильное тело — 400; слишком большое — 413.
- HTTP 200 возвращается только после завершения обработки. Сбой — 503 для повторной доставки.
- Повторные webhook-обновления подавляются в пределах одного процесса (24 часа, максимум 10 000 ID);
  параллельные дубли объединяются. После рестарта или в нескольких репликах возможен повтор ответа.
  Для текущих `/start`, `/id` и `/help` это означает максимум повтор сообщения; платёжных или каталожных записей нет.
- Polling продвигает offset только после успешной обработки, соблюдает `retry_after`,
  повторяет временные ошибки с задержкой и останавливается при 401/404/409.
- Запускайте ровно один экземпляр бота. Для будущих платежей/заказов понадобится отдельная
  постоянная очередь с идемпотентностью; она не входит в этот этап.
- Логи бота не включают токен, initData, webhook-секрет, текст обновлений или raw-ошибки HTTP.
- Реальное получение обновлений, кнопка Mini App и подпись от Telegram требуют ручного
  подключения вашего токена и доступного HTTPS-адреса. До этого end-to-end Telegram не подтверждён.
